## Findings addressed

1. User and role administration had no complete operator workflow despite existing auth/permissions. Added authenticated administration endpoints and UI. Password hashes/session secrets are excluded from responses. Password reset revokes sessions. Non-super administrators cannot grant roles or reset users with permissions beyond their own. Self-deactivation and changing one's own roles are rejected.
2. The frontend ignored the API's super-admin bypass and described role/permission payloads incorrectly. Updated session checks and TypeScript contracts to match the real API.
3. The message cursor used only a timestamp, so a page boundary could omit other messages in the same second. Added a deterministic ID tie-breaker and a real-DB regression test while retaining the old timestamp cursor contract.
4. Browser retries lacked an explicit idempotency key. Composer retries now reuse a generated key and clicks are synchronously guarded per destination. Actual delivery still belongs to the outbound worker.
5. Several major modules were absent, rather than merely hidden in navigation. Added actual persistence/API/UI for billing, terms, schedules, leave, saved replies, notifications and releases.
6. The existing destination-rate-limit tests shared Redis counters across independent tests. Reset only the isolated test namespace's rate-limit keys before each WhatsApp test. Updated a stale AI status assertion to include its existing `source` field.

Automated integration tests use the dedicated Postgres/Redis test containers.
